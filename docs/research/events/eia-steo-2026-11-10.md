calendar is wrong.** The proposal that created this entry called 2026-11-10 *"the Winter Fuels
Outlook edition — the one edition of the year carrying a distinct product"* and reasoned about

### Conviction legs, tested

1. **"The Winter Fuels Outlook edition" is REFUTED — it is an October product, on four primaries.**
   This is the finding, and it kills the reason this event exists as a distinct entry. The proposal
   that created it (from the `eia-steo-2026-10-06` sweep, 2026-09-08) states that
   `release_schedule.php` *"annotates that row as the Winter Fuels Outlook."* It does not. Parsed
   **cell by cell**, the table is `Issue | Release date | Notes`, and the note lands one row up:
   `['October 2026', '10/06/2026', 'Winter Fuels Outlook']`, then `['November 2026', '11/10/2026',
   '']`. **The 2027 rows repeat the pattern exactly** — `['October 2027', '10/13/2027', 'Winter
   Fuels Outlook']`, `['November 2027', '11/09/2027', '']` — so this is the schedule's standing
   shape, not a one-year quirk. The mechanism of the error is worth recording because it will recur:
   **stripped to flowed text the table reads `October 2026 / 10/06/2026 / Winter Fuels Outlook /
   November 2026 / 11/10/2026`**, and a note in a trailing Notes column looks like a heading for the
   line beneath it. Two further primaries settle it beyond the schedule page. The live STEO landing
   page still serves, inside an HTML comment, `We will release our <a
   href="/outlooks/steo/report/perspectives/2025/10-winterfuels/article.php">Winter Fuels
