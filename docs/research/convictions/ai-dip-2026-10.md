criteria 3 and 4). Nothing below is enforced in code until slice 4. Until then, the owner or a

- **Why the long call's expiry moves.** It sells at 45 days left. A call expiring before

  conviction's call. No budget changes either. The $50k long-call allocation (#5483) is an

- **S1-NVDA is steered, not narrowed.** Claim 5 *is* S1's study. Counting it again as conviction
  would count the same 15 of 15 twice.

## What this first instance taught the format (for slice 2)

- **A claim can cut against its owner.** Claim 7 says the near-term downside isn't finished.
  The format has to carry claims that argue against the view, or it only launders it.
- **One falsifier per row.** "Puts before, calls after" had two halves with different evidence
  and dates, so it became 2a and 2b. The data type should hold one falsifier per claim.
- **A claim that is already a playbook's evidence steers nothing new.** Claim 5 needs a pointer
  to S1-NVDA's study rather than a second weight. Otherwise one result counts twice.
- **The check is per pair today; the stance is aggregate.** #4469's check reads each
  subscription's own net P/L. Eric's stance judges the pairs together. Slice 2 has to pick one,
  and the stance says aggregate.
- **A check date can gate a pair whose evidence is a study.** If criterion 5 gates S1-NVDA on
  2027-01-29, S1's next entry (about 20 sessions before a ~2027-02-24 print, so ~01-26) opens
  before the check anyway. Proposal: a conviction gates only pairs running *as* conviction and
  cites the rest.
- **The lint needed one more directory.** `research:lint` now reads `docs/research/convictions/`
  with the same call-sheet contract. Owner, horizon, risk stance, check date and steered pairs
  aren't linted. They belong in slice 2's type.
