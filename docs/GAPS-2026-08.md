# Gap register — August 2026 full-repo review

_A systematic sweep of code vs. the project's own goals (CLAUDE.md north star, LIVING-UNIVERSE,
THE-GAME, GAMEBOARD-PLAN, BACKLOG, the AUTONOMY docs), run 2026-08-09. Three survey passes (vision
docs vs. code · the autonomy pipeline · server/observatory/ops), synthesized and ranked by Theory
of Constraints: what each gap blocks downstream, not how easy it is. Items marked **closed by this
review's PR** shipped with the register; everything else names its owner._

**Headline correction:** the docs' most-repeated blocker — "the history/persistence layer, the one
real blocker" (`THE-GAME.md`, `GAMEBOARD-PLAN.md` S5, `IDEAS.md`) — was already **built and wired**
(`src/observatory/history-store.ts`, `history-sampler.ts`, wired in `serve-dashboard.ts`). What was
actually missing: one `fly.toml` env line (prod samples were written to the container's ephemeral
disk and erased on every deploy) plus every derived consumer downstream. The docs mislabeled a
one-line repo edit as "the one Eric-owned op."

## Closed by this review's PR (plumbing, no taste/governance gate)

1. **Prod history durability** — `SKYNET_HISTORY_DIR = "/data/history"` in `fly.toml [env]`
   (the volume is already mounted for the `app` process). Every downstream item in §"waiting on
   history data" starts accruing the moment this deploys.
2. **Derived history metrics** — `src/observatory/history-metrics.ts`: windowed deltas
   (daily/monthly $ and %), seed baselines, the doubling trophies (`firstAccountToDouble`,
   `aggregateDoubling`) — the exact derived-state spec in `docs/BACKLOG.md`, as pure functions.
3. **The ceremony source seam** — `src/observatory/world-transitions.ts` derives
   `took_profit` / `deployed_capital` from consecutive equity samples; a `world_transition`
   variant rides the SSE event stream (reducer passes it through). This is the load-bearing
   dependency `LIVING-UNIVERSE.md` names for the entire event/ceremony vocabulary. What a ceremony
   *looks like* remains Eric's (visual, taste-gated).
4. **The daily-loss circuit breaker is now live** — `SafetyController.recordEquity` had **zero
   production callers** (a bot could ride an account to zero without halting, despite
   `AUTONOMY-DEPLOY.md` claiming the breaker was shipped). `src/autonomous/equity-watch.ts` marks
   the fleet to each cycle's quotes and feeds the breaker before every evaluation.
5. **The landmark is the scoreboard everywhere** — bot prominence (rank among peers) was computed
   but only reached the board cards; `/u/:id` and `/compare` rendered every Eye at full power. A
   single standings producer (`src/observatory/standings.ts`) now feeds all three views.
6. **Seed baseline at onboarding** — the founding equity sample is recorded the moment `/add`
   succeeds (`ParticipantService.recordSeedSample`). An unrecorded starting equity is permanently
   unreconstructable; every day this was missing was a lost baseline.

## Open — plumbing, buildable next (ranked by unlock)

1. **`WorldPatch` SSE channel.** `dashboard-server.ts` still re-`innerHTML`s the board per tick
   (the defect `GAMEBOARD-PLAN.md` D6 verified), destroying any canvas state. Blocks every live-
   board slice (S4), animated ceremonies (S5), and P2.2 autonomous-cycle streaming. Large;
   sequenced behind the S2 piece-contract taste check.
2. **Realized-P/L durability across restarts.** `reduce.ts` accumulates realized P/L in memory
   only and raw Alpaca reads don't carry it (`participant-snapshot.ts`), so it resets to 0 on
   every deploy — a false cliff in the history. Fix before ceremonies read big realized jumps.
3. **Member-added bots never trade.** `run-autonomous.ts` builds its roster from env vars only;
   the participant store `/add` writes is never read. A self-service bot renders with a persona
   chip and is autonomously inert. Needs a roster provider shared by both processes.
4. **Audit trail in prod.** `SKYNET_AUDIT_DIR` is set nowhere, and the `bots` process has no
   volume (`fly.toml [mounts] processes=["app"]`) — decisions are console-only, and the `/u/:id`
   decisions panel can never light up. The shared-storage choice (co-locate the runner vs. a
   shared store) is a hosting decision — flag to Eric with options.
5. **Session↔participant identity link.** `Participant` has no owner email; "YOU" is a display-
   name guess. `/add` has the session in hand and doesn't record the submitter.
6. **SIM/LIVE provenance labeling.** A stated brand invariant (`CLAUDE.md`, `LIVING-UNIVERSE.md`)
   with zero implementation: the dashboard never distinguishes offline-fixture from live data.
   One `mode` field on `DashboardData` + a badge (badge styling is taste — propose options).
7. **Testable autonomous runtime.** `run-autonomous.ts` (330 lines of production wiring) has no
   spec — which is exactly why the dead breaker and unset audit dir shipped as "✅". Extract
   `createAutonomousRuntime(deps)` on the proven `runCycle` pattern.

Also open (smaller): calendar-bucketed deltas on board/leaderboard/compare (the modules exist now;
the views don't read history yet) · `play-feedback.ts` is finished and imported by nothing · scan
gates skip docs-only PRs including `LESSONS.md`, the one doc a gate guards · `bot-broker` drops

`ParticipantSnapshot`/`EquitySample`.

**Closed 2026-08-13 — `scripts/config-audit.mjs` no longer needs a human to remember to run it.**
Deliberately **not** a CI gate wrapper (a GitHub Actions checkout can't see `data/duel-log.jsonl` —
it's `.gitignore`d, machine-local session history, so a fresh runner would always report check ③
"recurring intent themes" empty, silently blind to the audit's richest signal). Instead: a Routine
(`docs/COACHES.md` → *Special teams*) fires the real scan on a schedule into a session that has the
live log, and pushes Eric a notification only when it finds something. Still read-only, still a
proposal-surfacer, never a gate — see `docs/COACHES.md` for the reasoning.
